视频码率计算器 2.0 · Mac 离线图形版
====================================

最快使用方法
------------
1. 把整个文件夹或 ZIP 传到 MacBook Air，先解压。
2. 双击「视频码率计算器.html」，用 Safari、Chrome 或 Edge 打开。
   若默认打开了文本编辑器：右键 → 打开方式 → Safari。
3. 填写最终输出时长、上传上限、安全目标、音频总码率、封装预留。
4. 将蓝色数字填入 HandBrake 的视频 Average Bitrate（平均码率）。
5. 可复制完整设置，或导出 TXT；实际转码由 HandBrake 等软件完成。

计算器无需 Python、Node、FFmpeg、安装包或管理员权限。
它是本地单文件图形工具，不是已签名 / 已公证的原生 .app 或 .dmg。
Intel / Apple Silicon 无需分别下载，计算本身不依赖 CPU 架构。
保持 HTML 文件即可使用，不依赖旁边的开发文件，也不依赖互联网。
不要双击 Windows EXE，那不是 Mac 程序。

「打开计算器.command」只是可选的系统浏览器启动脚本。
ZIP 已记录它的 Unix 可执行权限；若 Mac 阻止脚本或提示权限问题，
直接打开 HTML 即可。无需关闭 Gatekeeper、清除隔离标记或更改系统设置。

默认示例与旧版一致
------------------
最终输出：9:38（578 秒）
上传上限：180 MB；安全目标：170 MB
全部音轨：128 kbps；封装及浮动预留：1.5%；附件：0
视频平均码率：2189 kbps
理论大小约 169.953 MB（162.079 MiB），并非最终编码大小保证。

先处理好「输出时长」
-------------------
预算应使用最终成片的时长，不是编码等待时间，也不是未裁剪原片长度。
支持 578、9:38、1:09:38.5、中文冒号；秒可带小数。
选择视频可在本机尝试读取原片时长，不上传视频；不支持的格式可手填。
浏览器无法读取 MKV / 某些 MOV / 损坏文件时，不影响手动计算。

有裁剪 / 变速：选择「从原片裁剪 / 变速换算」。
例：原片 10:00，保留 1:00～9:00，以 2 倍速播放，输出为 4:00。
只改 FPS 而保持播放速度不变，时长通常不变，不应把 60→30 当成两倍时长。
多个片段、补帧、变速曲线、尾部静帧等，请以剪辑软件的最终时间线为准。
换算只用于预算，不会替你裁剪、变速或导出视频。

大小与音轨
----------
MB = 1,000,000 字节；MiB = 1,048,576 字节；kbps = 1000 bit/s。
180 MB = 171.661 MiB；180 MiB = 188.744 MB。
同一页的上限、安全目标、附件预留使用同一单位。
网站没有明确说明时，选 MB 较保守；不要把 180 MiB 当成 180 MB。
「安全目标」必须小于上限；180 MB 的限制默认使用 170 MB，留约 10 MB 缓冲。

音频填所有输出音轨总和：一条 128→128，两条各 128→256。
128 kbps 可作为 AAC 立体声起点；多声道 / 音乐质量需求可能需提高。
填 0 代表实际输出也必须删除全部音轨。直通音频要按实际码率计算，
不能直通很大的无损音轨，却仍填 128。

预留百分比不是固定的容器开销。默认 1.5% 作为封装和浮动预算；
短片、多音轨、字幕 / 封面较多或偏差较大的硬编，可以增加预留、降低安全目标。
固定字幕 / 附件占用可另填「额外固定占用」，避免挤占视频预算。
若剩余视频预算低于 100 kbps，工具会报错；这个门槛沿用原版，不代表画质合格。

计算逻辑
--------
视频 kbps = floor(
  [目标字节 × (1 - 预留比例) - 附件字节] × 8 / 最终输出秒数 / 1000
  - 音频总 kbps
)
理论字节 = [(视频 kbps + 音频 kbps) × 秒数 × 125 + 附件字节]
           / (1 - 预留比例)

MB、无附件时，运算顺序保留旧版 bitrate_core.py 的公式。
视频码率统一向下取整；理论估计包含预留，不是文件字节精确预测。
页面和导出设置会同时显示 MB / MiB。
所有编码器得到相同容量预算；编码效率差异不会改变总空间。
旧版的分辨率 / 帧率经验阈值保留，但不当作画质保证，也不套用于硬编。
建议不得高于源片分辨率 / 帧率，源片没有的细节无法通过 10-bit 恢复。

HandBrake 起步设置
------------------
严格卡 180 MB：先试 x265 10-bit，Average Bitrate 填计算结果；
Multi-pass / 2-Pass 在当前编码器支持时开启。预设从 Medium 或 Slow 试起。
若网站不收 HEVC，改用 x264 / H.264 + MP4。
不要为卡体积而使用 RF / CQ 恒定质量模式；它不以输出体积为目标。
音频、裁剪范围和输出时长必须与计算器一致；删除多余音轨。
建议先编码同一段 30～60 秒高速运动素材看画质，再编码整段并检查真实体积。
片段测试可比较质量 / 速度，不能替代整片体积验收。
HDR 素材需另外确认色彩、位深和色调映射，避免无意洗白或错误转成 SDR。

Mac 软件比较和 FFmpeg 示例见「Mac压制软件选择.md」。
